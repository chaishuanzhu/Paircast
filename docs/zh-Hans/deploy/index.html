Paircast 服务端部署指南

Paircast 的服务端由两部分组成：Paircast 服务（Paircast 仓库 server/）负责账号、后台管理、片库和观影房间；开源 IM GO-IM 负责聊天和播放同步信令。本文用 Docker 把两者部署在同一台 Linux 服务器上，部署好后在 App 的「服务配置」里填服务器地址即可使用。

更多部署方式（Docker 全量、Kubernetes）和全部配置项见 GO-IM deploy/README.md 与 Paircast server/README.md。

0. 准备

项目说明
服务器Linux，2 核 2 GB 起；已装 Docker 20.10+ 与 Docker Compose v2
域名（推荐）如 im.example.com，解析到服务器，用于 HTTPS。仅局域网使用可以不要
发件邮箱（可选）任意支持 SMTP 的邮箱，用来给管理员和好友发初始密码；不配时初始密码在日志 / App 里显示
视频存储S3 兼容对象存储（阿里云 OSS、腾讯云 COS、七牛、MinIO 等）里放好的 mp4 / m4v / mkv，以及一对只读的访问密钥

1. 启动 GO-IM

mkdir go-im && cd go-im
base=https://raw.githubusercontent.com/chaishuanzhu/GO-IM/main/deploy/docker
curl -fsSLO $base/docker-compose.minimal.yml
curl -fsSLO $base/config.minimal.json

# 必改：JWT 签名密钥
sed -i.bak "s|CHANGE_ME_run_openssl_rand_base64_48|$(openssl rand -base64 48 | tr -d '\n/+=')|" config.minimal.json

账号由 Paircast 服务管理，GO-IM 自己的注册接口用不到，建议关掉：在 config.minimal.json 的 gateway.auth 里加 "disable_registration": true。

2. 在 GO-IM 登记 Paircast

Paircast 服务以「接入方」身份调用 GO-IM 的服务端 API。在 config.minimal.json 的 gateway 里加上：

"server_api": {
    "apps": [
        {
            "app_id": "paircast",
            "webhook_url": "http://paircast:8090/im/webhook",
            "webhook_events": ["group.member_left", "group.dismissed"]
        }
    ]
},

接入方密钥放在同目录的 apps.env（GO-IM 和 Paircast 服务都读这个文件），然后启动：

echo "GOIM_APP_PAIRCAST_SECRET=$(openssl rand -hex 32)" >> apps.env
echo "GOIM_APP_PAIRCAST_WEBHOOK_SECRET=$(openssl rand -hex 32)" >> apps.env

docker compose -f docker-compose.minimal.yml up -d
curl http://127.0.0.1:8080/health     # 返回 "status":"ok" 即就绪

这会启动 Gateway、MySQL、Redis 和 RustFS（存共享字幕、头像等小文件）。之后每次改 config.minimal.json、.env 或 apps.env，都执行下面的命令让 gateway 重新加载（下文简称「重启 gateway」）：

docker compose -f docker-compose.minimal.yml up -d --force-recreate gateway

3. 启动 Paircast 服务（账号与管理员）

在同一目录下载 Paircast 服务的 compose 文件和配置：

base=https://raw.githubusercontent.com/chaishuanzhu/Paircast/main/server/deploy/docker
curl -fsSLO $base/docker-compose.paircast.yml
curl -fsSLO $base/paircast.json

在 .env 里设置会话密钥、管理员邮箱和 Paircast 数据库账号的密码：

echo "PAIRCAST_SESSION_SECRET=$(openssl rand -hex 32)" >> .env
echo "PAIRCAST_ADMIN_EMAIL=you@example.com" >> .env
echo "PAIRCAST_MYSQL_PASSWORD=$(openssl rand -hex 16)" >> .env

邮件（SMTP）可选：配了之后，管理员和新用户的初始密码会发到各自邮箱；不配也能用，管理员初始密码写在 Paircast 服务日志里，新用户的初始密码直接显示在 App 里由管理员转交。要发信时在 paircast.json 里加：

"mail": {
    "enabled": true,
    "host": "smtp.exmail.qq.com",
    "port": 465,
    "username": "no_reply@example.com",
    "from": "Paircast <no_reply@example.com>"
}

SMTP 密码不要写进配置文件，放在 .env：PAIRCAST_MAIL_PASSWORD=你的SMTP密码。

片库在下一步配置，配好后一起启动。启动时 Paircast 服务会用 PAIRCAST_ADMIN_EMAIL 自动创建管理员账号，并把随机密码发到该邮箱（没配邮件或发送失败时写在 docker compose -f docker-compose.paircast.yml logs paircast 里）。用这个邮箱和密码在 App 登录，首次登录会要求改密码。

4. 片库与观影房间

4.1 接入视频存储

在 paircast.json 的 media.sources 里改成你的视频源（密钥不写在这里）：

"media": {
    "sources": [
        {
            "id": "oss",
            "name": "我的片库",
            "type": "s3",
            "s3": {
                "endpoint": "oss-cn-hangzhou.aliyuncs.com",
                "bucket": "my-videos",
                "region": "cn-hangzhou",
                "prefix": "films/",
                "use_ssl": true,
                "path_style": false
            }
        }
    ]
}

在 .env 里加上只读密钥，然后启动：

MEDIA_OSS_ACCESS_KEY=只读AccessKey
MEDIA_OSS_SECRET_KEY=只读SecretKey
docker compose -f docker-compose.paircast.yml up -d
docker compose -f docker-compose.paircast.yml logs paircast   # 出现 listening on :8090 即就绪

之后改 paircast.json、.env 或 apps.env，执行 docker compose -f docker-compose.paircast.yml up -d --force-recreate（下文简称「重启 Paircast 服务」）。App 片库会列出 prefix 下的 mp4 / m4v / mkv。

  • endpoint 填 S3 API 的地域域名（不含 https://），不要填 CDN 域名。七牛、MinIO 通常需要 "path_style": true。
  • 源 id 会写进影片 ID，上线后不要修改。id 不是 oss 时，在 docker-compose.paircast.yml 的 environment 里按 PAIRCAST_MEDIA_<大写ID>_ACCESS_KEY / _SECRET_KEY 的格式自行添加。
  • 可以配置多个源，App 片库页会出现片源切换。
  • 播放时服务器签发 6 小时有效的直链，视频流不经过服务器，所以密钥只需只读权限。
  • 账号、房间数据和刮削缓存存在 GO-IM 那台 MySQL 的独立库 paircast 里（专用账号 paircast，只能访问这个库；compose 里的 paircast-db 每次启动时自动建库建账号），共享字幕存在 RustFS，都不需要另外部署。

4.2 字幕与海报

  • 外挂字幕：和视频放在同一目录、同名即可，如 Inception.2010.mkv 配 Inception.2010.srt、Inception.2010.zh.ass、Inception.2010_en.vtt（支持 srt / vtt / ass / ssa）。
  • 海报与简介：优先读取同目录的 {主名}.nfo 与 {主名}-poster.jpg；没有时可以让服务器查 TMDB。
  • TMDB 刮削（可选）：.env 加 TMDB_ACCESS_TOKEN=…（TMDB 的 API Read Access Token），重启 Paircast 服务。
  • 在线字幕搜索（可选）：.env 加 OPENSUBTITLES_API_KEY=…，重启 Paircast 服务。

4.3 表情包（可选）

表情包放在某个片源的桶里，目录下要有 catalog.json 与 {pack_id}/pack.json。用 Paircast 仓库里的脚本整理并上传：

python3 Scripts/build-stickers.py --src /path/to/Stickers --out ./stickers-dist
PAIRCAST_S3_ACCESS_KEY=… PAIRCAST_S3_SECRET_KEY=… \
  python3 Scripts/upload-stickers.py --endpoint oss-cn-hangzhou.aliyuncs.com --bucket my-videos

上传需要可写密钥（只在你本机使用，不要放到服务器上）。然后在 paircast.json 的 media 里设 "stickers_source": "oss"、"stickers_prefix": "stickers/"，重启 Paircast 服务。

5. 反向代理与 HTTPS

App 只填一个服务器地址：/account、/console、/media、/room 转到 Paircast 服务（8090），其余转 GO-IM（8080）。用 Caddy 时它会自动申请证书并透传 WebSocket：

# /etc/caddy/Caddyfile
im.example.com {
    @paircast path /account/* /console/* /media/* /room/*
    reverse_proxy @paircast 127.0.0.1:8090   # Paircast 服务
    reverse_proxy 127.0.0.1:8080             # 其余转 GO-IM
}

完成后 App 里的服务器地址填 im.example.com。用 nginx 时记得透传 Upgrade / Connection 头。只在局域网用时不需要证书：把站点名 im.example.com 换成 :80，地址填 http://192.168.x.x。

6. 用户账号

Paircast App 不提供注册，账号都由管理员创建。

6.1 在 App 里添加用户

用管理员账号登录 App →「我的 → 后台管理 → 用户管理 → 右上角添加」→ 填好友的邮箱（昵称可不填）→ 添加。配了邮件时初始密码自动发到对方邮箱；没配或发送失败时页面直接显示初始密码，点「复制」后私下转交（离开页面后不再显示）。对方首次登录时必须修改密码。

用户可在 App「我的 → 删除账号」输入密码后自行注销（管理员账号除外）。忘记密码时，管理员可在「后台管理 → 用户管理」删除旧账号后用同一邮箱重新添加；同一页也可停用 / 启用账号。举报在「后台管理 → 举报」里处理，封禁会同时停用该账号。

6.2 用命令行创建（可选）

SERVER=https://im.example.com
curl -s -X POST $SERVER/account/login -d account=you@example.com -d password='管理员密码'
# 记下返回中的 "token"

curl -s -X POST $SERVER/console/users/create -H "Authorization: Bearer 上一步的token" \
  -d email=friend@example.com -d nickname=小明

没配邮件或邮件没发出去时，响应里会带 initial_password，请私下转交给好友。

7. 在 App 里使用

  1. 打开 Paircast → 登录页右上角「服务配置」→ 服务器地址填 im.example.com → 保存。
  2. 用管理员或好友的账号登录，在片库选片、开房间、发邀请链接。

详见 使用说明。

8. 日常维护

docker compose -f docker-compose.minimal.yml logs -f gateway        # GO-IM 日志
docker compose -f docker-compose.paircast.yml logs -f paircast      # Paircast 服务日志
docker compose -f docker-compose.minimal.yml pull && docker compose -f docker-compose.minimal.yml up -d     # 升级 GO-IM
docker compose -f docker-compose.paircast.yml pull && docker compose -f docker-compose.paircast.yml up -d   # 升级 Paircast 服务
GOIM_TAG=x.y.z docker compose -f docker-compose.minimal.yml up -d  # 固定 / 回滚版本（Paircast 服务用 PAIRCAST_TAG）
  • 生产环境建议在 .env 固定 GOIM_TAG 与 PAIRCAST_TAG，并定期备份 MySQL 与 RustFS 数据卷。
  • 修改默认数据库密码与 RUSTFS_SECRET_KEY（两个 compose 共用 .env，会一起生效），gateway.check_origin 填写实际域名。
所有密钥（JWT、会话密钥、SMTP、接入方密钥、存储、TMDB、OpenSubtitles）只放在服务器的 config.minimal.json / .env / apps.env 里，不要发给用户，也不要提交到 git。用户只需要服务器地址和自己的账号。
