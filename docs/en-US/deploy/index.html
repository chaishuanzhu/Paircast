Paircast Server Deployment Guide

The Paircast server is the open-source GO-IM. It handles accounts, chat, playback sync, watch rooms and the media library. This guide deploys the minimal setup on one Linux host with Docker. Once it is running, enter the server address in the app's Service Configuration.

Other setups (full Docker, Kubernetes) and every config field are documented in GO-IM's deploy/README.md.

0. What you need

ItemNotes
ServerLinux, 2 vCPU / 2 GB or more, with Docker 20.10+ and Docker Compose v2
Domain (recommended)e.g. im.example.com pointing at the server, for HTTPS. Not needed for LAN-only use
Mail accountAny mailbox with SMTP, used to send initial passwords to you and your friends
Video storagemp4 / m4v / mkv files in S3-compatible storage (Alibaba Cloud OSS, Tencent Cloud COS, Qiniu, MinIO, …) plus a read-only access key

Use a GO-IM release that includes the media library (the /media and /room APIs).

1. Start the server

mkdir go-im && cd go-im
base=https://raw.githubusercontent.com/chaishuanzhu/GO-IM/main/deploy/docker
curl -fsSLO $base/docker-compose.minimal.yml
curl -fsSLO $base/config.minimal.json

# Required: JWT signing secret
sed -i.bak "s|CHANGE_ME_run_openssl_rand_base64_48|$(openssl rand -base64 48 | tr -d '\n/+=')|" config.minimal.json

docker compose -f docker-compose.minimal.yml up -d
curl http://127.0.0.1:8080/health     # ready when it returns "status":"ok"

This starts the gateway, MySQL, Redis and RustFS (which stores small files such as shared subtitles and avatars). Whenever you change config.minimal.json or .env, recreate the gateway so it reloads (“restart the gateway” below):

docker compose -f docker-compose.minimal.yml up -d --force-recreate gateway

2. HTTPS (required on the public internet)

Put Caddy in front of port 8080. It obtains certificates automatically and passes WebSocket through:

# /etc/caddy/Caddyfile
im.example.com {
    reverse_proxy 127.0.0.1:8080
}

The server address in the app is then im.example.com. With nginx, forward the Upgrade / Connection headers. For LAN-only use you can skip this and enter http://192.168.x.x:8080.

3. Mail and the admin account

In-app email sign-up sends verification codes, and admin-created accounts get their initial password by email, so SMTP comes first (without it the app hides sign-up). Edit config.minimal.json:

"gateway": {
    "mail": {
        "enabled": true,
        "host": "smtp.example.com",
        "port": 465,
        "username": "no_reply@example.com",
        "from": "Paircast <no_reply@example.com>"
    },
    ...
},
"admin_email": "you@example.com"

Keep the SMTP password out of the config file; put it in .env next to it:

MAIL_PASSWORD=your-smtp-password

After restarting the gateway, it creates an admin account for admin_email and mails it a random password (if mail fails, the password is in docker compose -f docker-compose.minimal.yml logs gateway). Sign in to the app with that email and password; you will be asked to change the password the first time.

4. User accounts

4.1 Self sign-up (open by default)

Once SMTP works, friends tap Create Account on the app's login screen and sign up with an emailed code; no admin action needed. Code requests are rate-limited: one per email every 60 seconds, 10 per email per day, 20 per IP per hour.

Want to keep it private? Close registration in either of two ways:

  • Config file: set "disable_registration": true under gateway.auth in config.minimal.json, then docker compose -f docker-compose.minimal.yml up -d --force-recreate gateway.
  • At runtime: with an admin token, curl -s -X POST $SERVER/admin/settings -d uid=ADMIN_UID -d token=TOKEN -d registration_open=false (send true to reopen). Once changed this way, the database value wins over the config file.

When closed, the app hides the sign-up button; admins can still create accounts as below. Users can delete their own account in the app under Me → Delete Account after entering their password (admin accounts excepted).

4.2 Admin-created accounts

Exchange the admin credentials for a token, then create the account. The initial password is mailed to your friend, who changes it on first sign-in:

SERVER=https://im.example.com
curl -s -X POST $SERVER/login -d account=you@example.com -d password='admin-password'
# note "uid" and "token" in the response

curl -s -X POST $SERVER/admin/users/create \
  -d uid=ADMIN_UID -d token=TOKEN_FROM_ABOVE -d email=friend@example.com

If the mail could not be sent, the response includes initial_password; pass it on privately.

5. Media library

5.1 Connect your video storage

Add a source under gateway.media.sources in config.minimal.json (leave the keys out; they come from the environment in the next step):

"media": {
    "sources": [
        {
            "id": "oss",
            "name": "My Library",
            "type": "s3",
            "s3": {
                "endpoint": "oss-cn-hangzhou.aliyuncs.com",
                "bucket": "my-videos",
                "region": "cn-hangzhou",
                "prefix": "films/",
                "use_ssl": true,
                "path_style": false
            }
        }
    ]
}

Add the keys to .env (compose passes them to the gateway as GOIM_MEDIA_OSS_ACCESS_KEY / GOIM_MEDIA_OSS_SECRET_KEY):

MEDIA_OSS_ACCESS_KEY=read-only-access-key
MEDIA_OSS_SECRET_KEY=read-only-secret-key

Restart the gateway. When its log shows media library enabled, the app's Library lists the videos under prefix.

  • endpoint is the regional S3 API host without https://; do not use a CDN domain. Qiniu and MinIO usually need "path_style": true.
  • The source id becomes part of every movie ID, so don't change it later. If your id is not oss, add matching GOIM_MEDIA_<UPPERCASE_ID>_ACCESS_KEY entries to the gateway environment in the compose file.
  • You can add several sources; the Library screen then shows a source picker.
  • For playback the server issues links valid for 6 hours and the video stream bypasses the server, so a read-only key is enough.

5.2 Subtitles and posters

  • Sidecar subtitles: put them next to the video with the same name, e.g. Inception.2010.mkv with Inception.2010.srt, Inception.2010.zh.ass or Inception.2010_en.vtt (srt / vtt / ass / ssa).
  • Posters and overviews: {name}.nfo and {name}-poster.jpg next to the video are used first; otherwise the server can query TMDB.
  • TMDB (optional): add TMDB_ACCESS_TOKEN=… (your TMDB API Read Access Token) to .env.
  • Online subtitle search (optional): add OPENSUBTITLES_API_KEY=… to .env.

5.3 Stickers (optional)

Stickers live in the bucket of one of your sources, as catalog.json plus {pack_id}/pack.json. The Paircast repo has scripts to build and upload them:

python3 Scripts/build-stickers.py --src /path/to/Stickers --out ./stickers-dist
PAIRCAST_S3_ACCESS_KEY=… PAIRCAST_S3_SECRET_KEY=… \
  python3 Scripts/upload-stickers.py --endpoint oss-cn-hangzhou.aliyuncs.com --bucket my-videos

Uploading needs a writable key; use it only on your own machine, not on the server. Then set "stickers_source": "oss" and "stickers_prefix": "stickers/" under gateway.media.

6. Use it in the app

  1. Open Paircast → Service Configuration (top right of the login screen) → enter im.example.com → Save.
  2. Sign in with the admin or a friend's account, pick a title, open a room and send the invite link.

See the User Guide for details.

7. Maintenance

docker compose -f docker-compose.minimal.yml logs -f gateway       # logs
docker compose -f docker-compose.minimal.yml pull && docker compose -f docker-compose.minimal.yml up -d   # upgrade
GOIM_TAG=x.y.z docker compose -f docker-compose.minimal.yml up -d  # pin / roll back
  • In production, pin GOIM_TAG in .env and back up the MySQL and RustFS volumes regularly.
  • Change the default database passwords and RUSTFS_SECRET_KEY, and set gateway.check_origin to your domain.
Every secret (JWT, SMTP, storage, TMDB, OpenSubtitles) stays in the server's config.minimal.json / .env. Never send them to users or commit them to git. Users only need the server address and their own account.
